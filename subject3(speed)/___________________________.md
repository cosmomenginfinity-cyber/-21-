# 返航逻辑与视觉跟随转弯半径调试便条

日期：2026-08-12

## 一、当前返航到底是什么类型

当前返航不是“只依靠里程计和记录航向角”的一维返航，而是：

> 编码器与陀螺仪组合航位推算当前 XY，对倒序记录的 XY 路径执行二维倒车 Pure Pursuit；编码器累计里程负责路径进度、速度规划和末端停车。

### 1. 去程记录内容

去程每行驶约 0.20 m 记录一次：

- 当前 X、Y 坐标；
- 当前航向角 yaw；
- 编码器累计里程；
- 当前车轮速度。

当前 XY 的计算不是对加速度二次积分，而是：

```text
x += encoder_speed × cos(yaw) × dt
y += encoder_speed × sin(yaw) × dt
```

因此：

- 编码器速度提供每周期位移；
- 陀螺仪积分航向决定这段位移投影到哪个方向；
- 两者共同得到当前 XY。

### 2. 返航开始

返航时从 RAM 将去程记录倒序读出，然后将整条记录路径旋转、平移到当前返航起点坐标系。

这一步允许当前坐标原点与记录坐标原点不同，但要求返航起点附近的当前姿态和记录末端姿态能够正确对齐。

### 3. 返航转向控制

每个控制周期执行：

1. 读取当前航位推算 XY 和 yaw；
2. 将当前 XY 投影到最近的记录路径线段；
3. 得到连续、单调的路径进度；
4. 沿记录路径向前寻找动态前视点；
5. 在线段间插值得到目标 XY；
6. 计算当前车辆到目标 XY 的方位角；
7. 以倒车运动方向 `当前 yaw + 180°` 计算 PP 误差；
8. 输出真实前轮目标角。

倒车 PP 的核心形式为：

```text
alpha = 目标方位角 - (当前yaw + 180°)
delta = -atan(2 × 轴距 × sin(alpha) / 目标点距离)
```

记录航向角主要用于：

- 返航坐标系对齐；
- 路径航向插值；
- 曲率计算和速度规划；
- 航向误差显示。

它不是当前转向控制唯一或主要的目标量，真正决定 PP 打角的是当前 XY 与目标 XY 的几何关系。

### 4. 里程的用途

编码器累计里程用于：

- 定义各记录点的路径累计进度；
- 计算返航已行驶和剩余距离；
- 弯前减速、末端减速；
- 最终停车；
- 超程判断。

所以当前方案可准确称为：

> 编码器—陀螺仪航位推算的二维 XY 倒车 PP，里程负责进度与停车。

## 二、视频中去程跟随轨迹的主要现象

结合 5 段有效视频（第 5、6 段是相同文件）观察：

- 车辆的转向和航向变化总体连续；
- 没有明显的高频左右反打；
- 外部画面中没有发现高架相机相对车身的大幅周期性摆动；
- 人车距离总体较稳定，距离—加速度环已经具备可用性；
- 最明显现象是：人横向换向后，车辆沿人的运动轨迹内侧切过去；
- 部分弯道人在接近锥桶后才改变方向，横向变化较突然；
- 车辆当前追的是“人的实时位置”，不会自动完整复现人刚刚跑过的圆弧。

因此目前的主要矛盾更接近：

> 人的领跑走线、实时目标追踪产生的内切，以及高速动态前视过长共同放大了转弯半径和切弯问题。

既然比赛路线以弧线和大弯为主、直道稳定性已基本满足，下一阶段优先减小安全转弯半径是合理的。

## 三、为什么恢复前视距离上限可能改善弯道

### 1. 当前视觉转向公式

视觉先将色块转换为车体坐标目标点 `(target_x, target_y)`：

```text
alpha = atan2(target_y, target_x)
Ld = 0.95 + 0.50 × 实际车速
delta = atan(2 × L × sin(alpha) / Ld)
```

其中：

- `alpha`：目标相对车头方向的方位角；
- `L=0.58 m`：轴距；
- `Ld`：动态前视参数；
- `delta`：目标真实前轮角。

虽然头文件定义了：

```text
COLOR_FOLLOW_LOOKAHEAD_MAX_M = 1.90 m
```

但当前最大值限制代码被注释，因此它实际没有生效。

### 2. 高速时前视距离会变得很长

```text
1.0 m/s → Ld=1.45 m
2.0 m/s → Ld=1.95 m
3.0 m/s → Ld=2.45 m
3.5 m/s → Ld=2.70 m
4.0 m/s → Ld=2.95 m
```

你们的去程速度上限均在 3 m/s 以上，因此当前实际前视通常明显超过 1.90 m。

### 3. 同一目标偏角下，前视越长，打角越小

假设 `alpha=20°`：

```text
Ld=2.45 m → delta≈9.2°
Ld=1.90 m → delta≈11.8°
Ld=1.70 m → delta≈13.1°
```

从 2.45 m 限制到 1.90 m，目标轮角大约增加 28%。

### 4. 前视距离与瞬时转弯半径的关系

车辆自行车模型：

```text
R = L / tan(delta)
```

而 PP 公式给出：

```text
tan(delta) = 2L × sin(alpha) / Ld
```

合并可得：

```text
R = Ld / [2sin(alpha)]
```

因此在相同 `alpha` 下，瞬时转弯半径与 `Ld` 成正比。

从 2.45 m 限制为 1.90 m：

```text
R新/R旧 = 1.90/2.45 ≈ 0.776
```

理论瞬时转弯半径约减小 22.4%。

限制为 1.70 m 时：

```text
R新/R旧 = 1.70/2.45 ≈ 0.694
```

理论瞬时半径约减小 30.6%。

### 5. 为什么可能改善实际轨迹

当前视频中的典型过程是：

1. 人开始横向转弯；
2. 车辆仍沿原方向前进一段；
3. 目标方位误差继续积累；
4. 算法随后才给出足够轮角；
5. 车辆用一条内侧弦线追向人。

恢复 1.90 m 上限后：

- 人刚开始横移时目标轮角就会更大；
- 车头更早建立旋转；
- 横向误差不必积累到很大；
- 轨迹更可能成为连续圆弧，而不是先前冲、再急追。

因此前视上限主要针对：

- 高速下转向增益被持续稀释；
- 入弯初段曲率不足；
- 车头航向建立过晚；
- 外摆后再切弦追目标。

### 6. 为什么不是一定改善

必须区分两种现象。

#### A. 转向太迟、半径过大

表现：

- CH0/CH1 已经出现目标偏差；
- CH2 目标轮角增长仍然慢；
- CH3 可以跟上 CH2；
- 车辆先向外冲，随后才转向。

这种情况恢复前视上限通常会改善。

#### B. 车辆追实时目标而切人轨迹内侧

人在圆弧上跑时，车辆与人的连线是圆弧的弦，弦天然位于圆弧内侧。

恢复前视上限可以让打角更及时，却不能根治“只追当前目标而不沿目标历史轨迹行驶”。如果转向增益太大，车辆甚至可能更靠近锥桶。

因此先测试 1.90 m，而不是直接降到很小。

### 7. 前视过短的代价

小角度下：

```text
delta ≈ 2L × alpha / Ld
```

转向灵敏度近似与 `1/Ld` 成正比。相对当前 2.45 m：

```text
1.90 m → 转向增益约 ×1.29
1.70 m → 约 ×1.44
1.50 m → 约 ×1.63
1.20 m → 约 ×2.04
```

前视太短会同步放大：

- 色块像素抖动；
- 人腰部摆动；
- 相机小角度振动；
- 距离测量变化；
- 视觉延迟造成的相位滞后。

因此要逐级找到转弯半径与稳定性的边界。

### 8. 横向加速度也会增加

```text
ay = v²/R
```

缩小半径但保持相同高速，会增加轮胎侧滑、车尾外甩和出弯反摆风险。因此最终需要将缩短前视与弯道速度限制配套。

## 四、具体减小转弯半径的调试顺序

### 第一步：先固定人的领跑走线

软件不变，先用粉笔或胶带标记人的轨迹：

- 不要到锥桶旁才突然转向；
- 在锥桶前约 2～3 m 开始连续转向；
- 使用圆弧或平滑 S 形过渡，不跑折线；
- 人的路线应比希望车辆走出的路线稍宽；
- 入弯前轻微收速，车头完成换向后再提速；
- 弯心不要突然加速，以免人车距离、速度命令和动态前视同时增大。

可围绕单个锥桶画三条领跑弧线：

```text
2.5 m、2.2 m、1.9 m
```

每条重复三次，记录车辆外缘到锥桶的最小间隙和用时。

### 第二步：恢复最大前视限制

先只恢复：

```c
else if (lookahead > COLOR_FOLLOW_LOOKAHEAD_MAX_M)
{
    lookahead = COLOR_FOLLOW_LOOKAHEAD_MAX_M;
}
```

测试顺序：

| 版本 | 最大前视 | 目的 |
|---|---:|---|
| A | 当前不限幅 | 基线 |
| B | 1.90 m | 验证高速前视过长是否为主因 |
| C | 1.70 m | 进一步压缩转弯半径 |
| D | 1.50 m | 寻找稳定边界 |

每个版本保持相同的：

- 人和领跑路线；
- 速度上限；
- 色块位置；
- 距离环参数；
- 中心滤波；
- 转向内环。

不要一次同时改多个参数。

### 第三步：用无线示波器判断

- CH0：原始像素误差；
- CH1：目标横向偏差；
- CH2：算法目标轮角；
- CH3：实际轮角；
- CH4：实际车速；
- CH5：横摆角速度；
- CH6：视觉帧龄。

理想变化：

```text
CH0开始偏移
→ CH2更早增大
→ CH3紧跟CH2
→ CH5更早建立
→ 实际轨迹半径缩小
```

问题对应关系：

- CH0已偏移、CH2仍慢：前视过长或视觉横向计算太保守；
- CH2及时、CH3滞后：转向执行机构或内环成为限制；
- CH2/CH3连续但车尾滑动：横向加速度过大，需要弯道限速；
- CH6在弯中明显升高：视觉处理延迟或丢帧；
- 半径缩小但更贴锥：实时目标内切成为主要矛盾，应扩大人的轨迹或改历史轨迹跟随。

### 第四步：增加弯道速度限制

根据目标轮角估算转弯半径：

```text
R = WHEEL_BASE / tan(|目标轮角|)
```

根据允许横向加速度计算弯道速度：

```text
v_curve = sqrt(a_y_max × R)
最终目标速度 = min(距离环速度, v_curve)
```

初期可用：

```text
a_y_max = 4.0 m/s²
```

对应参考值：

| 转弯半径 | 弯道速度上限 |
|---:|---:|
| 1.5 m | 2.45 m/s |
| 2.0 m | 2.83 m/s |
| 2.5 m | 3.16 m/s |
| 3.0 m | 3.46 m/s |

这样大弧仍能超过 3 m/s，小半径换向会提前降速。

### 第五步：必要时升级为目标历史轨迹跟随

如果最大前视降至 1.5～1.7 m 后仍明显切弯，不应继续无限缩短前视。此时主要矛盾是车辆只追人体当前位置。

可升级为“面包屑”跟随：

1. 用车体 XY、yaw 和视觉相对位置计算人体全局 XY；
2. 人每移动约 0.15～0.20 m 保存一个轨迹点；
3. 车辆追踪人体历史轨迹上的前视点，而不是直接追人体当前位置；
4. 距离—加速度环继续负责纵向速度；
5. 历史轨迹 PP 负责横向方向。

这样车辆会沿人刚刚跑过的弧线行驶，能从根本上减少实时目标追踪产生的内切。

## 五、建议的近期结论

当前最值得执行的顺序是：

```text
固定并外扩人的领跑弧线
→ 恢复1.90 m前视上限
→ 测试1.70 m
→ 加入按目标轮角计算的弯道限速
→ 仍切弯再考虑目标历史轨迹
```

恢复 1.90 m 上限的本质不是“凭经验增加转向”，而是一次干净的诊断实验：验证高速下转弯半径是否主要受到动态前视持续增大、转向增益被稀释的限制。
