视觉跟随加速度闭环与弯道方案

一、为什么高速时人与车的稳定距离会变远

当前控制基本相当于：

    speed_cmd = Kp * (range - desired_range)

当人以 2 m/s 匀速前进时，车辆也必须输出 2 m/s 才能相对静止。因此系统必须始终保留一定的距离误差：

    稳态距离误差 ≈ 人的速度 / Kp

如果 Kp=0.8，人以 2 m/s 前进，则稳态距离误差约为 2.5 m，再加上距离死区，正好解释了高速时车辆为什么离人很远。

二、改为加速度型距离闭环是否合理

这个思路合理且可行，并且比当前“距离直接映射速度”的方式更适合维持固定跟随距离。

建议控制形式：

    distance_error = range - desired_range
    relative_speed = distance_error 的变化率

    accel_cmd =
        Kp_distance * distance_error
      + Kd_relative * relative_speed

    speed_cmd += accel_cmd * dt

对应关系：

- 色块高度小、测得距离较远：距离误差为正，产生正加速度。
- 色块高度大、测得距离较近：距离误差为负，产生负加速度。
- 距离合适且人与车同速：加速度为零，保留上一周期速度。
- 人开始加速、距离逐渐扩大：相对速度为正，车辆提前加速。
- 人减速、距离快速缩短：相对速度为负，车辆提前减速。

这相当于“车距弹簧＋相对速度阻尼”。只用距离误差产生加速度也能运行，但容易在预设距离附近前后振荡，所以相对速度阻尼项很重要。

三、不要直接使用像素高度误差控制加速度

像素高度与距离是反比例关系。直接用像素误差，会造成远处控制偏弱、近处控制突然变强。

继续先计算米制距离：

    range = calibrated_distance * calibrated_height / measured_height

然后在米制距离上完成闭环。

初始参数可以从以下范围开始测试：

    Kp_distance = 1.0～1.5   // m/s² per m
    Kd_relative = 1.0～1.8   // m/s² per (m/s)

只在获得新视觉帧时更新距离和相对速度，相对速度必须使用真实视觉帧间隔计算，不能把每帧都当成 10 ms。100 Hz 控制中断可以保持最近一次加速度，并以 0.01 s 累加目标速度。

四、避免重复的速度斜坡

现有后轮控制内部已经有速度斜坡。如果视觉层先积分产生目标速度，内部又通过很慢的速度斜坡跟随，会形成额外滞后。

更合适的结构是：

    视觉距离误差与相对速度
              ↓
          产生加速度
              ↓
       对加速度限幅并积分一次
              ↓
           目标速度
              ↓
       左右后轮速度 PI

不要再叠加第二个反应迟缓的加速度过程。

五、“瞄准图像中心和色块中心的中点”是否合理

如果使用：

    aim_x = (image_center_x + target_center_x) / 2

那么横向像素误差实际上被减半，目标转角会变小。它会使转向更加柔和，但通常会加重切弯，并不能使车辆恢复人走过的圆弧路径。

切弯的根本原因是：车辆只知道人当前的位置，不知道人刚才沿什么路径绕过了锥桶。

人在锥桶外侧走的是圆弧，但车辆直接追逐人的当前位置，得到的是圆弧内部的一条弦，所以会切向锥桶内侧。维持更近的固定距离能够明显减轻这个问题，因为距离越近，弧线和弦的差别越小，但不能从原理上完全消除切弯。

六、真正解决切弯：跟随人的历史轨迹

推荐保存人最近经过的位置，而不是每帧只追逐人的当前位置：

    人经过的位置：P0 → P1 → P2 → P3
    车辆依次跟随：P0 → P1 → P2 → P3

每次识别到目标时，将目标相对坐标结合车辆编码器和 IMU 转换到统一坐标系，并保存最近一段轨迹点。车辆从轨迹中选择合适的前视点进行 Pure Pursuit。

这样人绕锥桶走出圆弧，车辆也会沿着相同轨迹绕过去，而不是直接朝人的当前位置切线前进。

可以分两步实现：

1. 简化版：保存最近 1～2 秒的目标位置，补偿车辆自身移动后，选择距离车辆约 0.7～1.0 m 的历史轨迹点作为 PP 目标。
2. 完整版：将目标位置转换到惯性坐标系，形成动态“面包屑轨迹”，车辆沿该轨迹进行 PP。

现有工程已经具有编码器、IMU、Pure Pursuit 和路径记录模块，因此具备实现基础。

七、实现目标轨迹前，先加入弯道速度限制

可以根据前轮角或路径曲率连续限制车速：

    curvature = tan(wheel_angle) / wheelbase
    speed_cap = sqrt(lateral_accel_limit / (abs(curvature) + epsilon))
    speed_cmd = min(speed_cmd, speed_cap)

这样直线仍然可以达到 2 m/s，但在人开始大幅横移、车辆进入大转角时会自动降低速度。相比固定的转角分档，这种限制过渡更加连续。

还可以计算目标方位角及其变化率：

    bearing = atan2(target_y, target_x)
    bearing_rate = (bearing - last_bearing) / frame_dt

当方位角或方位角变化率快速增大时：

- 提前降低速度；
- 缩短转向前视距离；
- 保持更加积极的转向响应。

它不能完全替代轨迹记忆，但能明显减少高速进入弯道时的切线冲出。

八、推荐实施顺序

1. 将纵向控制改成“距离误差＋相对速度阻尼 → 加速度 → 速度累加”，解决高速稳态距离变远。
2. 加入按转角或曲率连续降速，避免车辆以 2 m/s 直接进入大弯。
3. 测试固定距离后切弯现象是否已经足够轻微。
4. 如果仍会撞锥桶，实现目标历史轨迹或面包屑跟随。
5. 最后增加目标运动预测，补偿约 30 FPS 的视觉采集和处理延迟。

结论：加速度型距离闭环是正确方向；图像中心与目标中心取中点不适合作为主要弯道方案；真正解决绕锥桶切弯的方法，是“固定车距＋弯道降速＋跟随人的历史轨迹”。
